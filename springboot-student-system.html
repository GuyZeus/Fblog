Spring Boot 学生信息管理系统：从零搭建完整项目

📅 2026年7月20日🏷️ Spring Boot, Java⏱️ 约 12 分钟阅读

本文记录了我在课程项目中使用 Spring Boot + MyBatis + MySQL 搭建学生信息管理系统的完整过程。这个项目涵盖后端 API 设计、数据库建模、前后端分离实践，以及最终的 Docker 容器化部署。

一、技术选型

  • 后端框架：Spring Boot 3.2 — 约定优于配置，开箱即用
  • 持久层：MyBatis-Plus — 简化 CRUD，代码生成器提高效率
  • 数据库：MySQL 8.0 — 主流关系型数据库
  • 前端：原生 HTML + CSS + JS（课程要求，不引入框架）
  • 部署：Docker + 1Panel + Nginx 反向代理

二、数据库设计

系统核心是一张 student 表，字段如下：

CREATE TABLE student (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  student_no  VARCHAR(20)  NOT NULL UNIQUE COMMENT '学号',
  name        VARCHAR(50)  NOT NULL COMMENT '姓名',
  gender      TINYINT      NOT NULL COMMENT '0-男 1-女',
  age         INT          COMMENT '年龄',
  major       VARCHAR(50)  COMMENT '专业',
  phone       VARCHAR(20)  COMMENT '联系电话',
  create_time DATETIME     DEFAULT CURRENT_TIMESTAMP
);

三、Controller 层设计

采用 RESTful 风格，统一的返回结果封装：

@RestController
@RequestMapping("/api/students")
public class StudentController {
    @Autowired
    private StudentService studentService;

    @GetMapping
    public Result<List<Student>> list() {
        return Result.success(studentService.list());
    }

    @PostMapping
    public Result<Void> add(@RequestBody @Valid Student student) {
        studentService.save(student);
        return Result.success();
    }
}

四、前后端分离

前端通过 fetch 调用后端接口，处理 JSON 数据。关键点是配置 CORS 解决跨域问题：

@Configuration
public class CorsConfig {
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/api/**")
                        .allowedOriginPatterns("*")
                        .allowedMethods("GET", "POST", "PUT", "DELETE");
            }
        };
    }
}

五、Docker 部署

使用 Dockerfile 将应用打包为镜像，再配合 docker-compose 编排应用与数据库：

FROM eclipse-temurin:17-jdk
COPY target/student-system.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app.jar"]
踩坑提示：MySQL 容器数据卷一定要挂载到宿主机，否则容器重建后数据全丢。

六、总结

通过这个项目，我完整走通了「需求分析 → 数据库设计 → 后端开发 → 前端联调 → 部署上线」的全流程。最大的收获是理解了前后端如何通过 HTTP 接口协作，以及容器化部署带来的环境一致性优势。
