MySQL 索引优化实战：从执行计划到慢查询排查

📅 2026年4月20日🏷️ MySQL, 数据库⏱️ 约 12 分钟阅读

数据库性能优化是后端开发的核心技能。本文从 EXPLAIN 执行计划入手，讲解索引优化的实战方法。

一、EXPLAIN 怎么看

EXPLAIN SELECT * FROM student WHERE name = '张三';

重点关注 type（访问类型）、key（实际用到的索引）、rows（扫描行数）、Extra（额外信息）。

二、索引类型

  • 普通索引：最常见的 B+Tree 索引
  • 唯一索引：列值必须唯一
  • 组合索引：多列联合，遵循最左前缀原则
  • 覆盖索引：查询字段都在索引中，无需回表，性能极佳

三、最左前缀原则

组合索引 (a, b, c) 能命中 a、(a,b)、(a,b,c)，但不能跳过 a 直接查 b。

四、慢查询排查

SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;

五、总结

索引不是越多越好——它拖慢写入、占用空间。根据查询模式设计索引，用 EXPLAIN 验证，才是正确姿势。
