区别于第三方企业邮箱、免费邮箱，这套系统完全自主可控，只用一个域名即可批量生成无数个子邮箱，个人注册、验证码接收、日常收发邮件全部自给自足。

## 为什么要自建 Cloud-Mail 邮箱系统？

日常使用公共邮箱存在不少痛点：Gmail、QQ邮箱容易收到垃圾邮件，临时注册网站不想暴露个人主邮箱；付费企业邮箱年费成本高，批量创建别名邮箱限制多。

市面上开源邮箱方案大多需要 VPS、邮件服务器、反解析配置，运维复杂。而 Cloud-Mail 基于 Cloudflare Workers 开发，全程无服务器，依靠 Cloudflare 免费额度就能满足个人长期使用需求，完美解决低成本自建邮箱的需求。

技术栈分工清晰：Vue3 + Element Plus 做前端页面展示，Hono 作为 Workers 后端框架，搭配 D1 数据库、KV缓存、R2对象存储，整套代码结构规范，二次开发门槛低。

## Cloud-Mail 核心功能一览

- **多域名批量邮箱**：绑定自有域名，无限生成 xxx@你的域名 临时邮箱、长期邮箱；
- **完整收发邮件**：集成 Resend 实现邮件发送，支持附件、图片、群发；收件自动存入系统，支持草稿、星标、归档分类；
- **附件存储**：使用 Cloudflare R2 存储所有邮件附件，无流量扣费；
- **消息推送**：新邮件自动转发至 Telegram 机器人或备用邮箱，实时提醒；
- **管理员后台**：RBAC权限管控，管理所有用户、限制收发额度、查看系统数据；
- **开放API接口**：支持批量创建账号、接口查询邮件，可对接自己的其他项目；
- **安全防护**：内置 Turnstile 人机验证，防止恶意批量注册垃圾账号；
- **个性化自定义**：自定义登录页背景、网站标题、界面透明度；配套ECharts数据看板，查看收发邮件统计数据。

## 项目整体架构

### 1. mail-worker（后端服务）

部署在 Cloudflare Workers，负责邮件接收、接口处理、数据库读写、权限校验；依赖 D1 存储用户与邮件数据，KV做登录缓存，R2存放附件。配置文件 wrangler.toml 统一管理所有云资源绑定信息。

### 2. mail-vue（前端网页）

Vue3 响应式管理后台，电脑、手机自适应布局，登录后可查看收件箱、发邮件、修改个人配置、查看数据统计，打包后静态资源可通过 GitHub Pages / Cloudflare Pages 托管。

## 完整部署流程

### 方案：Cloudflare 原生部署（推荐，完整邮件功能）

1. Fork 本仓库到自己 GitHub 账号；
2. Cloudflare 后台创建 D1 数据库、KV命名空间、R2存储桶，记录所有ID；
3. 注册 Resend 并验证域名，获取发送邮件 API Key；
4. 仓库 Settings → Secrets，填入 Cloudflare 账号ID、API令牌、域名列表、JWT密钥等参数；
5. 开启仓库 Actions，自动构建部署 Workers 后端；
6. 前端 Vue 打包上传至 Cloudflare Pages，绑定域名访问邮箱后台。

## 部署踩坑记录

- **云资源绑定丢失**：项目代码更新重部署后，D1/KV/R2绑定会失效，需要重新在 Workers 设置中绑定资源，执行初始化接口同步数据库；
- **域名邮件解析失败**：域名必须在 Cloudflare 托管，配置对应 Email DNS 记录，否则无法接收外部邮件；
- **静态资源路径异常**：GitHub Pages 二级子仓库部署前端时，打包需要配置二级基础路径，否则页面样式、接口请求全部404；
- **JWT密钥泄露风险**：密钥不能硬编码进代码，必须存放于仓库Secret，否则他人可伪造登录管理员账号；
- **免费额度限制**：Cloudflare 免费版 Workers、D1、R2 有每日限额，大量收发邮件会触发限流，个人轻度使用无压力。
